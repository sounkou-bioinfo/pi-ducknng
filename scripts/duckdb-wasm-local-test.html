ducknng browser wasm demo

This page loads the ducknng DuckDB extension in duckdb-wasm, runs the browser smoke checks, and then exposes a small SQL shell against the same connection. The local/header-served browser page is intentionally narrow: extension load, codec and registry calls, and a diagnostic raw inproc:// URL-launched AIO / framed manifest path for pthread-capable runtimes. The Playwright harness around this page also proves browser HTTP client, AIO, table, HTTPS/CORS, framed RPC/session helpers, and asynchronous WS/WSS frame carriers against local test endpoints. On GitHub Pages, where cross-origin isolation is supplied by a service worker, the page loads the extension and enables the SQL shell but skips the inproc:// transport proof unless the host can provide real COOP/COEP headers.

Browser ipc://, raw tcp://, native POSIX-style tls+tcp://, generic socket handles, and listeners are unsupported. Browser HTTP(S) and asynchronous WS/WSS clients use browser-managed TLS; synchronous WS/WSS RPC is intentionally rejected.

Setup and smoke tests

The threaded runtime needs cross-origin isolation. On GitHub Pages this page installs a same-origin service worker and reloads once to add COOP/COEP headers.
