- Fixed a remotely reachable memory-safety defect in Quack ENUM type decoding. `ducknng_quack_read_type_info()` accepted `ExtraTypeInfo` fields 200 (value count) and 201 (label list) in either order. Sending 201 first with zero values passed the count check while both were zero and allocated a one-slot `enum_labels` array; a following field 200 then published an `enum_count` of up to 2^24 against that allocation. Shape validation, `ducknng_quack_node_free_contents()`, and `duckdb_create_enum_type()` all walk `enum_count` entries, giving a heap over-read, `duckdb_free()` on unallocated pointers, and dereference of those pointers as C strings — reachable from any untrusted schema in an RPC reply body or an `upload_append` payload. `enum_count` is now assigned only where the labels are allocated, so the free path is bounded by construction, and field 201 before field 200 is rejected for every type carrying both. Covered by a native property regression asserting which check fires and by four tracked ENUM corpus seeds; the corpus previously contained no ENUM sample at all, which is why coverage-guided fuzzing never generated the reordering.

NULL from that function now means only that the message could not be built.

## ducknng 0.1.2 — TLS and codec hardening release

- Added native incremental asynchronous HTTP response streams without changing unary `ducknng_ncurl_aio()` semantics. `ducknng_ncurl_stream_open_aio()` exposes status and duplicate-preserving headers before body completion; `ducknng_ncurl_stream_recv_aio()` provides one cancellable bounded raw-body receive at a time; dedicated collectors report body slices and explicit EOF; and `ducknng_ncurl_stream_close()` owns final connection cleanup. The native adapter handles Content-Length, close-delimited bodies, and chunked transfer decoding below callers, leaving SSE/NDJSON parsing above the transport. Browser builds fail closed for this new surface until a `ReadableStream` backend exists. SQL lifecycle coverage and the external Python HTTP smoke test exercise early headers, cancellation, dechunked incremental reads, EOF, and explicit cleanup.
This release fixes verified security issues in outbound TLS client verification, HTTP header handling, and the Quack-derived row codec. The extension metadata is bumped to 0.1.2.

- Added Arrow-encoded positional SQL parameters for `exec`, `query_open`, and `query_prepare`, with nested DuckDB values, null handling, a 65,535-parameter limit, and no SQL text interpolation. New SQL helpers expose parameterized row queries, scan-time unary execution, and schema-only remote prepare. `query_prepare` now rejects multiple statements before any statement can run.
- Made remote SQL execution semantics inspectable and accurate. `ducknng_list_methods()` now projects the complete method descriptor policy; `query_open` advertises that it can mutate; dynamic-schema query helpers are documented for read-only/idempotent work; fixed-schema `run_rpc` sends during scan so `EXPLAIN` cannot trigger a remote write. Network execution does not claim exactly-once delivery.
- Fixed `check_news.py --base` so committed `NEWS.md` changes satisfy the gate; the old filter removed `NEWS.md` before checking for it and made every committed user-visible arc fail.
- Made the runtime manifest and legacy descriptor generator report the same `0.1.2` version as package metadata.
- Hardened parameter capability discovery and decoding: manifests and handshakes list only active parameter-capable methods, malformed Arrow child counts fail before indexing, and descriptor byte limits serialize without LLP64 truncation.
- Added the browser `ws://`/`wss://` frame carrier (#11), the last step of the capability-driven browser-support restructure. It is a *ducknng-frame-over-WebSocket* carrier (not NNG SP-over-WS, which a browser cannot speak) with both halves. Server (`src/ducknng_ws_frame.c`): a raw-WebSocket message-mode nng stream listener that comes up beside the HTTP RPC mount, sharing the same nng HTTP server at a `/ws` sibling path (`ws://host:port/<path>/ws`, `wss://` under TLS); each persistent connection reads one binary WS message as a ducknng frame and dispatches it through the same admission/authorization/accounting/session gate as HTTP — factored into `ducknng_service_authorize_and_dispatch_frame()` so both carriers are byte-identical — then replies with one binary message. Client (`src/ducknng_wasm_ws_bridge.c`): a persistent JS `WebSocket` per URL riding the existing fetch completion-queue op table + pump, correlating replies FIFO per socket; it is async-only (browsers have no synchronous WebSocket receive, so the synchronous RPC path rejects `ws://`/`wss://` and points at `*_rpc_aio`). `caps.websocket` moves to `supported` for the wasm backends, so the client routes ws/wss to the carrier on the browser while native ws/wss keeps using the NNG SP socket. Native ws/wss (SP) and HTTP carriers are unchanged. A native round-trip test (`test/ws_smoke.py`, `make ws_smoke`) drives the server endpoint with a raw-WS client — the exact wire a browser drives — covering persistent multi-frame reuse, a malformed frame answered by an error frame, and recovery.
- Added the `ducknng_upload_table(url, source_query, target_table[, tls_config_id])` client table function that closes out the #9 upload lane end-to-end: it runs source_query on the runtime's pooled connection, opens an upload session on the remote, streams each result chunk as a `ducknng_quack_batch` in an upload_append frame, and commits, returning `rows_uploaded` and client-sent `bytes_uploaded`; on any error it sends upload_abort so the server rolls back and no partial upload persists. The upload runs once at execution (a table function's bind may be invoked repeatedly). Batch column names, order, and types must match the target exactly. A new materialized-result encoder (`ducknng_result_materialized_chunks_to_quack_payload`, using duckdb_result_get_chunk) feeds duckdb_query results into the quack codec, since the streaming encoder only handles session streams. Covered by test/sql/ducknng_upload_roundtrip.test (row count + checksum, append semantics, and a type-mismatch that aborts and rolls back).
- Added the server-side upload lane methods for #9: upload_open (JSON {target_table, mode append}; v1 appends to an existing table -- acquires a session connection, BEGINs a transaction, opens an appender, registers an upload session), upload_append (frame body = the append prefix + a quack batch, decoded straight into the session appender, returning the running row count), upload_commit (flush + COMMIT, returns rows), and upload_abort (rolls back). They are registered via ducknng_register_upload_methods()/ducknng_register_upload_methods(require_auth) and gated like the exec method, so a service exposes no upload surface unless the host opts in. Execution-subject admission, session owner tokens, and per-peer-identity limits are reused from the query-session path. The upload_append body is advertised with its own `ducknng_upload_append` payload format (counted `[session_id][token_len][token]` prefix + quack batch); the counted token is matched over its full length, and batch column names/order/types must match the target exactly (rejected before any append) since the appender is ordinal. Quack identifier fields (column names, nested child names, enum labels) carrying an embedded NUL are rejected at decode so a counted name like `a\0x` cannot match target column `a`. upload_commit closes the appender before destroying it and rolls the transaction back if that finalize step reports an error, so a deferred constraint violation at close never commits a half-finalized upload. Upload and query control methods reject each other's sessions. docs/protocol.md documents the upload lane contract; create-from-schema mode is a documented follow-up.
- Added the upload-append frame prefix parser (ducknng_upload_append_parse_prefix) for the #9 upload lane: an upload_append request body is a fail-closed control prefix ([session_id u64 LE][token_len u16 LE][token]) followed by the raw quack batch, so a request identifies its session and carries binary batch data in one frame. The parser validates the fixed header and token length against the buffer before exposing any slice; a property test fuzzes it against random bytes.
- Added upload-session lifetime state for the #9 upload lane: a ducknng_session can now hold an open appender inside an open transaction on its pinned connection (ducknng_service_add_upload_session), and session teardown destroys the appender and rolls the transaction back on abort, idle prune, or shutdown so partially uploaded rows never persist. The upload_open/append/commit/abort methods and the ducknng_upload_table client wrap this next.
- Added the server-side quack decode-to-appender primitive that the upload lane (#9) builds on: `ducknng_quack_payload_parse_schema` (extracted from the table-function bind path so both share one fail-closed header parser) and `ducknng_quack_payload_append_to_appender`, which decodes a `ducknng_quack_batch` and appends its chunks to an open DuckDB appender, failing closed on any malformed byte, schema/appender column mismatch, or append error. A new property test fuzzes the parse_schema header against random bytes. The table-function decode path is unchanged.
- Added a capability-gated browser conformance mode (#8 step 6): `node test/browser/run_smoke.mjs --probes=conformance` reads `ducknng_transport_capabilities()`, asserts the scalar descriptor and the active `ducknng_list_transport_capabilities()` row agree, then runs each transport probe whose capability is supported, skips unsupported ones cleanly, and runs experimental ones report-only. The wasm Pages workflow now gates publishing on this conformance run against a wasm_eh artifact instead of a bare load probe, so a broken artifact or a claim/behavior drift fails before anything is published. The async fetch bridge also now enforces the same browser HTTP host-allowlist and configured-header policy as the synchronous XHR path.
- Browser AIO is real async (#8 step 4): `ducknng_ncurl_aio(...)` and the framed HTTP request aio launch a `fetch` with an `AbortController` registered in a JS op table and return a pending handle; completions settle when the DB worker event loop runs between queries and are folded into the handle at every read. `ducknng_aio_cancel` aborts the in-flight fetch and is immediately observable, `timeout_ms` arms a JS timer that aborts on expiry, and waits degrade to a poll because the single-threaded event loop cannot progress inside a query. Launch failures remain terminal error handles. The synchronous `ducknng_ncurl` path keeps the blocking XHR bridge. The wasm capability rows now report real async with timeout and cancel honored, and the browser probe suite asserts pending/cancel/timeout semantics directly.
- The wasm Pages workflow now gates publishing on a headless-Chromium load probe of the built artifact (with retries for wasm_threads resource sensitivity), so an extension that fails at LOAD can no longer ship silently as the demo release.
- Fixed a browser extension-load regression introduced by the Quack length-arithmetic hardening: LLVM fuses the portable overflow-check-then-multiply idiom into a 128-bit multiply, and duckdb-wasm side modules do not link compiler-rt, so the module imported `__multi3` with an ABI signature the pinned duckdb-wasm runtime does not export. The builtin is now compiled into the side module (`src/ducknng_wasm_builtins.c`), removing the import entirely; verified by the full local Chromium probe suite.
- The HTTP frame carrier joined the net-backend boundary (#8 steps 3/5): `ducknng_http_frame_client_open/transact/transact_msg` dispatch through the backend vtable with verbatim native and browser implementations, so no `__EMSCRIPTEN__` fork remains in shared HTTP client control flow. Verified by the native suite and the full browser probe run including framed RPC and session routing.
- The transport capability contract is now data for every build target (#8 step 2): `ducknng_list_transport_capabilities()` returns the per-target matrix (native, wasm_eh, wasm_threads) with exactly one active row, and `make wasm_matrix` renders the docs/wasm.md transport matrix from it, so the support table is generated from the compiled contract instead of hand-maintained prose. The scalar descriptor's backend names are now the build-target names (`native`, `wasm_eh`, `wasm_threads`).
- Introduced the net-backend boundary (#8 step 1): a build-target `ducknng_net_backend` vtable now routes the synchronous HTTP exchange, with the native NNG client and the browser XHR bridge as its two implementations — `ducknng_http_transact` itself no longer forks on `__EMSCRIPTEN__`. A new `ducknng_transport_capabilities()` scalar returns the active backend's machine-readable capability descriptor (per-transport support level, async semantics, TLS ownership) so harnesses can gate on the contract instead of per-target probe lists. Behavior is unchanged on both targets.
- Added `docs/browser_support.md` as the implemented browser contract: one `ducknng_net_backend`, a machine-readable capability descriptor, one promise-to-AIO bridge, pluggable frame carriers, and capability-gated conformance.
- Streaming query sessions now carry the opener's execution subject (#7): `ducknng_service_acquire_session_connection` binds the admitted subject (authorizer principal, else verified peer identity) to the pooled session connection, and every release path — open failure, close, prune, idle timeout, service stop — removes the binding before the connection can be reused. Subject-restricted HTTP profiles therefore resolve inside session-executed SQL across open/fetch, and never leak to the next user of the pooled connection. The connection-bound subject takes precedence over the thread-local request subject during profile resolution and listing, so a fetch request authorized as a different principal cannot substitute its own subject for the session opener's.
- Renamed the pre-auth service limits from `max_*_per_principal` to `max_*_per_peer_identity` (`max_inflight_per_peer_identity`, `max_reply_bytes_per_peer_identity`, `max_session_open_rate_per_peer_identity`), including the `ducknng_list_servers()` columns and error messages. These counters were always keyed by the verified TLS peer identity and enforced before the SQL authorizer maps a principal; the old names implied post-auth semantics they never had. Behavior is unchanged. Post-auth per-subject quotas, if ever needed, will be a separate explicit layer.
- Subject-scoped `ducknng_list_http_profiles()`: inside service-handled SQL the listing returns only unrestricted profiles and profiles admitted to the current execution subject, with the `allow_subjects_json` column withheld, so request-context callers cannot enumerate other subjects' endpoint scopes or admission lists. Host/local SQL outside any request context keeps the full redacted listing.
- Added execution-subject admission for outbound HTTP profiles (#6). `ducknng_register_http_profile(...)` accepts an optional `allow_subjects_json` argument: a non-empty JSON array of subjects that may resolve the profile. ducknng services install the effective subject (SQL authorizer `principal` when present, otherwise the verified peer identity) around RPC method dispatch and HTTP route/stream handling, and bind it to the DuckDB connection executing the request SQL so admission survives DuckDB worker-thread pipelines. Restricted profiles fail closed for ad-hoc SQL outside any request context, unrestricted profiles behave exactly as before, and the subject context is host/internal only — it is never settable from SQL. `ducknng_list_http_profiles()` gains an `allow_subjects_json` column, and the route-local `auth_allow_identities_json` check now uses the same strict exact-match JSON string-array parser instead of a substring probe, so malformed allowlists fail closed.
- Hardened outbound TLS clients for `tls+tcp://`, `wss://`, and `https://`: when a supplied TLS handle is used in client mode, `auth_mode = 0` now means verify the remote server certificate by default rather than mapping to `NNG_TLS_AUTH_MODE_NONE`. Server/listener mode keeps the existing semantics where `auth_mode = 0` does not require client certificates, and `auth_mode = 2` remains the required-mTLS setting. Regression coverage now starts TLS and HTTPS services with one CA and verifies that clients configured with a different CA fail closed instead of connecting silently.
- Hardened `headers_json` request and response handling. Header names were already token-checked; header values are now rejected if they contain CR, LF, NUL, tab, DEL, or any other control character, including through JSON escapes such as `\r`, `\n`, and `\u000a`. The validation is shared by `ducknng_ncurl(...)`, `ducknng_ncurl_aio(...)`, `ducknng_ncurl_table(...)`, route response headers, explicit response content types, stream route content types, and `ducknng_http_headers_build(...)`, preventing CRLF/header-injection style values from reaching NNG HTTP APIs.

Reader offset checks use subtraction-form bounds checks, blob lengths that do not fit `size_t` are rejected before casting, fixed-width vector byte counts use checked multiplication, list/array child sizes and row counts are range-checked, cumulative row counts cannot wrap, and a single source chunk cannot exceed DuckDB's output vector capacity. Malformed Quack-derived bodies now fail with a codec error instead of risking heap out-of-bounds reads or writes.

The existing randomized property tests continue to fuzz wire, transport, size arithmetic, and Quack skip paths with fixed seeds for reproducibility.

The self-published release workflow now also smoke-checks header control-character rejection, malformed Quack rejection, profile auth-header collisions, and TLS client CA verification on native loadable release artifacts.

## ducknng 0.1.0 — first sealed release

The 0.1.0 public API is sealed. Names, contracts, and method schemas in the current implementation and documentation are stable and should not change casually. All must-resolve items in `docs/api_sealing_checklist.md` are resolved.

### What is included and stable

**Transport.** `ducknng_start_server(...)` accepts `inproc://`, `ipc://`, `tcp://`, `tls+tcp://`, `ws://`, `wss://`, `http://`, and `https://`. The URL scheme selects the transport family; NNG and HTTP/HTTPS share one server entrypoint with `contexts = 1` for the HTTP carrier. Synchronous and AIO request, RPC, and session helpers route by scheme automatically.

**Socket patterns.** All six NNG socket families are supported and tested with dedicated coverage: pair, push/pull, pub/sub, surveyor/respondent, bus (hub-and-spoke broadcast and fully-connected all-pairs in `test/sql/ducknng_bus_mesh.test`), and poly.

**AIO.** Raw request, unary RPC, session (open/fetch/close/cancel), and HTTP AIO helpers share one handle lifecycle: launch returns a handle, `ducknng_aio_collect(...)` collects or polls, `ducknng_aio_drop(...)` releases. `ducknng_aio_collect_decoded(...)` layers structured convenience. `ducknng_aio_status(...)` exposes terminal state. `ducknng_aio_wait(...)` waits without collecting.

**Query sessions.** `query_open` returns a bearer `session_token`; `fetch`, `close`, and `cancel` must present it with the session id. mTLS-verified peer identity is an additional owner constraint when present. `ducknng_fetch_query_table(...)` is the one-fetch decoded-table convenience path. Raw session variants (`ducknng_open_query_raw`, `ducknng_fetch_query_raw`, `ducknng_close_query_raw`, `ducknng_cancel_query_raw`) return one reply frame for use inside HTTP route handlers.

**Execution models.** `ducknng_set_service_execution_model(...)` switches between `shared_serialized_connection` (default), `service_serialized_connection`, and `request_connection`.

**TLS.** `ducknng_self_signed_tls_config(...)` and `ducknng_tls_config_from_files(...)` accept PEM material from paths or in-memory strings. Handles are reusable across servers and client calls.

**HTTP route framework.** `ducknng_register_http_route(...)` and `ducknng_register_http_route_pattern(...)` mount exact, prefix, and template routes beside the framed RPC endpoint. Strict header/query/cookie/path parsers, named request accessors, and one-row response-builder helpers are part of the public surface. Routes are not manifest methods.

**Body codecs.** `ducknng_parse_body(blob, content_type)` dispatches to built-in decoders for JSON, Arrow IPC, ducknng frames, text, and raw. CSV/TSV/Parquet are recognised but use the `body BLOB` fallback. `ducknng_register_codec(...)` and `ducknng_unregister_codec(...)` extend the set at runtime.

**Method registry and manifest.** Methods are registered through descriptors and appear in the manifest exported by `ducknng_get_rpc_manifest(...)` and the built-in `manifest` RPC method.

**Admission and security.** Fast C admission: required mTLS, exact peer-identity allowlists, IP/CIDR allowlists, and service limits (`max_open_sessions`, `max_active_pipes`, `max_inflight_requests`, `max_sessions_per_peer_identity`). SQL authorizer callbacks via `ducknng_set_service_sql_authorizer(...)`. Per-principal in-flight caps, cumulative byte limits, and session-open rate limits are explicitly deferred — service-level limits are the stable admission contract.

**Arrow IPC type contract.** Normative two-way types: `BOOLEAN`, `TINYINT`–`BIGINT`, `UTINYINT`–`UBIGINT`, `FLOAT`, `DOUBLE`, `VARCHAR`, `BLOB`, `DATE`, `TIME`, `TIME_NS`, `TIMESTAMP_S`/`MS`/`US`/`NS`, `DECIMAL`, `LIST`, `STRUCT`. Emit-only projections: `HUGEINT` as `decimal128(38,0)`, `UUID` as `utf8`, `TIMESTAMP_TZ` as timezone-free `timestamp[us]`, `ENUM` as resolved `utf8`, `MAP` as Arrow `map`, `UNION` as Arrow `dense_union`. Explicitly deferred: dictionary-preserving roundtrips, extension types, run-end encoding, `UNION` input decoding, per-principal rate limits, large UTF-8/binary, fixed-size binary, duration, timezone-aware timestamp semantics. See `docs/types.md`.

**Pipe monitor.** `ducknng_read_monitor(...)` and `ducknng_list_pipes(...)` expose per-service NNG pipe event telemetry.

### What is explicitly deferred (not blocking 0.1.0)

- Dictionary-preserving Arrow roundtrips, extension types, run-end encoding, `UNION` input decoding
- Per-principal in-flight caps, cumulative byte limits, session-open rate limits
- Large UTF-8/binary, fixed-size binary, duration, timezone-aware timestamps
- Static assets, HTTP-carrier streaming, route-local authentication policy, worker lifecycle management
- CSV/TSV/Parquet body parsing via a memory-backed reader (generic `body BLOB` fallback is stable)
- Future DuckDB-native Arrow re-plumb using `unstable_new_arrow_functions` if that API stabilises

## Planned next steps

- Keep future async additions on the current aio substrate: add lifecycle, wait, collect, and decode conveniences only when they preserve the one-pending-operation handle model.

- Keep tightening lifetime and concurrency behavior around runtime-owned sockets, sessions, and aio handles now that the transport matrix is broader.
